## How the priority was decided

Rank is set by, in order, using only workbook evidence:

1. PAGE MAP & META priority (P1 before P2).
2. 90 DAY ROADMAP window (Week 3 for manned guarding, CCTV and electric fencing; Weeks 6-7 for events, K9, alarm response and VIP).
3. Number of P1 keywords mapped to the page in KEYWORD MASTER (more first).
4. PAGE MAP row order, where the first three tie (K9, alarm response, VIP).

No search volume, difficulty, CPC or ranking is used: the workbook marks all of them Not validated. The P1 counts per cluster in the CLUSTER STRATEGY sheet equal the P1 counts used here. Readiness is reported separately and does not change the rank.

## Sequence

**Wave 1 (roadmap Week 3): manned guarding, CCTV installation, electric fencing.** These are the three P1 pages. Together they hold 123 of the 250 service keywords and 40 of the 81 service P1 keywords.

**Wave 2 (roadmap Weeks 6-7): events security, K9 unit, alarm response, VIP close protection.** Alarm response has the heaviest claim burden: 6 of its 31 keywords promise speed or 24-hour availability, and its response model (item AR1) blocks publication. Plan it last in the wave unless Operations can document its response model sooner.

Before any page starts: close the shared items C1, C2, C7, C8, C9, C10 and C11 for that page, answer owner decisions D1 to D4, and keep the Blog noindex. Wave 2 can begin in parallel once Wave 1 proves the page architecture.

## Audit of existing service wording

The live site describes each service in one sentence plus a protection-layer line. This is all the approved wording that exists; the briefs use nothing else.

| Service id | Name | Existing description | Layer | Slug in workbook |
|---|---|---|---|---|
| `manned-guarding` | Manned Guarding | Security guards stationed at the sites and entrances you choose. | Access | `/services/manned-guarding/` |
| `cctv-installation` | CCTV Installation | Supply and installation of CCTV camera systems. | Eyes | `/services/cctv-installation/` |
| `electric-fencing` | Electric Fencing | Installation of electric fencing along property boundaries. | Perimeter | `/services/electric-fencing/` |
| `events-security` | Events Security | Security personnel for public and private events. | People | `/services/events-security/` |
| `k9-unit` | K9 Unit Services | Dog and handler teams as part of a site's security arrangements. | Response | `/services/k9-unit-services/` |
| `alarm-response` | Alarm Response | Response to alarm activations. | Response | `/services/alarm-response/` |
| `vip-close-protection` | VIP Close Protection | Personal protection for individuals and their movements. | People | `/services/vip-close-protection/` |

Findings:

- Each service has one sentence of copy. That is not enough to build a useful, non-thin page; every brief therefore needs owner-supplied scope (C1, C2).
- The K9 service id is `k9-unit` but the workbook slug is `k9-unit-services`. Keep the id for the enquiry form and use the workbook slug for the URL.
- Workbook URLs end with a slash. The site's routing has no trailing slash, so canonical, sitemap and links must all use the slash-less form (see `page-architecture.md`).
- The protection layers file states its headlines are visual framing, not claims. 'Every alarm, answered.' still reads as a promise and is flagged on the alarm brief.
- No photo may be shown: every entry in `lib/photo-library.ts` has pending clearance.
- The downloadable company profile and brochure conflict with the site in several ways (evidence document, section 4).
