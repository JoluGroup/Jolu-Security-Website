# Publishing acceptance checklist

Generated by `scripts/seo/build-service-docs.mjs`. Do not hand-edit. Use once per service page. A page is accepted only when every row is checked with its proof attached to the pull request.

| Done | Area | Check | Source | Proof |
|---|---|---|---|---|
| [ ] | Governance | Every blocking evidence item for the page (C1, C2, C7-C11 and the page's own publication-level items) is closed with a recorded source. | ROADMAP dependencies | Evidence table filled in, reviewed by the named owner. |
| [ ] | Governance | Every statement on the page traces to existing approved wording or to owner-supplied evidence. Nothing comes from the legacy PDFs without evidence. | lib/claims.ts policy | Line-by-line source note in the pull request. |
| [ ] | Governance | No claim in lib/claims.ts is rendered unless its status is approved with evidence recorded. | lib/claims.ts | Claims registry diff; claims tests pass. |
| [ ] | Governance | The owner approved the page layout and any change to the homepage service cards or footer links. | Design freeze | Written owner approval. |
| [ ] | Indexation | The route is added to LIVE_PAGES with indexable true only in the publishing change, and appears in the sitemap exactly once at its canonical URL. | TECHNICAL AUDIT: Indexation | Sitemap test and built sitemap.xml. |
| [ ] | Indexation | Canonical is absolute, self-referencing and slash-consistent with the site's routing (no trailing slash), and robots meta is not noindex. | TECHNICAL AUDIT: Indexation | Built HTML head. |
| [ ] | Indexation | A live-site crawl confirms the slug and that no redirect or duplicate URL exists for the page. | EXECUTIVE DASHBOARD: slugs are proposals | Crawl export saved with date. |
| [ ] | Information architecture | One page per intent: the page's keywords are not targeted by any other page, and related-service links add no duplicate content. | TECHNICAL AUDIT: Information architecture | Keyword mapping test. |
| [ ] | Information architecture | The homepage links to the page (service card and footer) and the page links back to the homepage and its enquiry form. | TECHNICAL AUDIT: internal linking from homepage | Built HTML link check. |
| [ ] | Information architecture | Internal links to unpublished pages (offices, guides, related services) are absent. | No broken links | Link-resolution test. |
